# ДЗ №1. Подробный разбор запуска Titanic

[Короткий отчёт с результатами и скриншотами](hw-1.md)

## Что делает каждая команда

Команды выполняются из корня репозитория, где лежит
[`pyproject.toml`](../pyproject.toml).

### 1. `uv sync --locked`

Создаёт окружение `.venv` и устанавливает в него зависимости проекта,
включая scikit-learn, Ruff и pre-commit. Версии берутся из
[`uv.lock`](../uv.lock). Если файл нужно обновить, например после изменения
зависимостей в `pyproject.toml`, флаг `--locked` приводит к ошибке. Так можно
проверить, что проект действительно устанавливается из зафиксированного набора
версий.

### 2. `uv run pre-commit install`

Устанавливает локальный Git-хук `.git/hooks/pre-commit`. При обычном
`git commit` Git запускает этот хук, и pre-commit проверяет Python-файлы,
подготовленные к коммиту. Если проверка падает, коммит останавливается.
Установку хуков повторяют в каждом новом клоне, если хотят включить
автоматическую проверку перед коммитами.

### 3. `uv run pre-commit run --all-files`

Запускает проверки вручную по всем отслеживаемым Python-файлам. В этом проекте
[`ruff check`](../.pre-commit-config.yaml#L3) ловит, например, неиспользуемые
импорты, а [`ruff format --check`](../.pre-commit-config.yaml#L8) проверяет
форматирование. При успехе рядом с обеими проверками появится `Passed`.
Ручная проверка работает и без установки Git-хука.

### 4. `uv run python -m src.get_data`

Запускает [модуль загрузки](../src/get_data.py#L12). Он скачивает Titanic
№40945 с OpenML без токена, проверяет SHA-256 и записывает файл в
`data/raw/titanic.arff`. При успехе команда выводит путь к файлу и его
контрольную сумму.

### 5. `uv run python -m src.train`

Запускает [модуль обучения](../src/train.py#L23). Он читает скачанный ARFF,
делит пассажиров на обучающую и тестовую выборки с фиксированным seed,
обучает логистическую регрессию и оценивает её на тестовой выборке.
В `artifacts/model.pkl` сохраняется модель вместе с предобработкой, а в
`artifacts/metrics.json` — accuracy, ROC-AUC и размеры выборок. Метрики также
появятся в терминале.

## Частые вопросы

### 1. Куда я как человек должен указать дополнительные зависимости?

Выполни `uv add matplotlib` из корня проекта.
Для инструмента разработки используй `uv add --dev pytest`.

### 2. То есть `pyproject.toml` тоже автоматически обновляется? И `uv.lock` тоже?

Да. `uv add` добавит зависимость в `pyproject.toml`,
обновит `uv.lock` и установит библиотеку.

### 3. Можно ли менять `pyproject.toml` руками, как `requirements.txt`?

Да. В этом
проекте список `[project].dependencies` играет похожую роль для основных
зависимостей. После ручной правки запусти `uv sync`. Он обновит `uv.lock`
и приведёт окружение `.venv` в соответствие с новым списком зависимостей.
В Git добавь оба файла.

### 4. В `pyproject.toml` я тоже вижу версии. Чем же всё-таки `uv.lock` отличается от `pyproject.toml`?

`pyproject.toml` задаёт допустимые
версии, например `pandas>=2.2,<3`. `uv.lock` фиксирует выбранные версии, включая
зависимости этих библиотек. В нашем проекте для pandas выбрана `2.3.3`,
и `uv sync --locked` установит именно её.

### 5. Зачем везде `uv run`?

Он запускает команды в окружении проекта.
Вручную активировать `.venv` не нужно.

### 6. Что значит `python -m`?

Python находит и запускает модуль по имени.
Например, `src.get_data` соответствует файлу `src/get_data.py`.

### 7. Что нужно делать каждый раз?

Окружение настраивают при первом запуске
или после изменения зависимостей, хук устанавливают один раз на клон.
Данные скачивают, если файла ещё нет. Проверки и обучение можно повторять
по мере работы. Повторное обучение перезапишет модель и метрики.

### 8. Что означают метрики?

Accuracy показывает долю верных прогнозов.
ROC-AUC показывает, насколько хорошо модель ставит выживших выше
невыживших по предсказанной вероятности при сравнении пар пассажиров.

### 9. Почему в GitHub нет датасета и модели?

Их создают команды загрузки
и обучения. Папки `data/raw/` и `artifacts/` указаны в
[`.gitignore`](../.gitignore).

### 10. `uv run pre-commit install` запускает пакет или какой-то файл?

По порядку участвуют и пакет, и файл.

1. `uv run` запускает команду `pre-commit` из окружения проекта. Эту команду предоставляет одноимённый Python-пакет.
2. Подкоманда `install` создаёт исполняемый скрипт `.git/hooks/pre-commit`. Достаточно выполнить её один раз в каждом клоне.
3. При `git commit` Git запускает этот скрипт. Скрипт вызывает пакет `pre-commit`, который читает [настройки проекта](../.pre-commit-config.yaml#L1) и запускает Ruff для подготовленных к коммиту Python-файлов. Если проверка падает, коммит останавливается.

Чтобы проверить весь проект вручную, используй `uv run pre-commit run --all-files`.
Для этой команды установка Git-хука не требуется.

### 11. Что за функциональность у `.git/hooks/pre-commit`?

Это Git-хук — исполняемый скрипт, который Git автоматически запускает
перед созданием коммита. Если скрипт возвращает ненулевой код завершения,
Git останавливает коммит. В нашем проекте так происходит, когда Ruff находит
ошибку. [Документация Git о хуках](https://git-scm.com/docs/githooks#_pre_commit)

Git-хук хранится в локальной папке `.git/`. В новом клоне нужно выполнить
`uv run pre-commit install`, чтобы подключить проверки к `git commit`.
Список проверок хранится в репозитории. [Настройки pre-commit](../.pre-commit-config.yaml#L1)
